# Architecture: Брендбук-генератор (userver)

## 1. Общее описание

Бэкенд реализован на **C++** с использованием фреймворка **userver**.  
Сервис предоставляет REST API для мобильного приложения и фронтенд-редактора.    
Интеграция с **Yandex AI Studio** (LLM) и **векторной БД** (для RAG) вынесена в отдельные компоненты.

---

## 2. Компоненты userver

Все компоненты оформлены как `userver::components::ComponentBase` и подключаются через конфигурационный файл.

### 2.1. Компонент `LLMClientComponent`

**Назначение**  
Отвечает за взаимодействие с внешним API LLM.  
Поддерживает два режима:
- **Первичная генерация** — по текстовому описанию создаёт векторное представление (JSON/SVG).
- **Редактирование через чат** — принимает текущее состояние проекта и новое сообщение пользователя, возвращает обновлённое состояние.

**Интерфейс**
- `GenerateProject(description, context)` → возвращает сгенерированные данные.
- `EditProject(current_data, user_message)` → возвращает обновлённые данные.

---

### 2.2. Компонент `PromptConstructorComponent`

**Назначение**  
Формирует **промпты** для LLM на основе:
- пользовательского текстового запроса,
- текущего состояния проекта (если редактирование),
- релевантных примеров из векторной БД (если используется RAG).

**Интерфейс**  
- `BuildGenerationPrompt(user_description, examples)` → возвращает готовый промпт.
- `BuildEditPrompt(current_state, user_message, examples)` → возвращает промпт для правки.

**Зависимости**  
- `VectorSearchComponent` (для получения примеров).

---

### 2.3. Компонент `VectorSearchComponent`

**Назначение**  
Осуществляет **поиск по векторной БД** для извлечения релевантных примеров стилей, цветовых палитр, композиций и т.п.  
Это повышает качество генерации за счёт RAG (Retrieval-Augmented Generation).

**Интерфейс**  
- `FindSimilar(embedding, limit)` → возвращает список примеров (метаданные + векторные данные).

**Зависимости**  
- `PostgresComponent` (или специализированный клиент для векторной БД).

---

### 2.4. Компонент `VersionStorageComponent`

**Назначение**  
Отвечает за **сохранение, чтение и восстановление версий проектов**.  
Каждая версия — это полный слепок данных проекта в момент сохранения (SVG + метаданные).  
Данные версий хранятся в объектном хранилище, а метаинформация — в PostgreSQL.

**Интерфейс**  
- `SaveVersion(project_id, data, source, comment)` → сохраняет новую версию, возвращает её ID.
- `GetVersion(project_id, version_id)` → возвращает данные версии.
- `ListVersions(project_id, limit, offset)` → возвращает список версий с метаданными.
- `RestoreVersion(project_id, version_id)` → восстанавливает состояние проекта из указанной версии.

**Зависимости**  
- `PostgresComponent` (для метаданных версий).

---

### 2.5. Дополнительные вспомогательные компоненты

- **`AuthComponent`** — JWT-валидация, управление сессиями.
- **`ProjectManagerComponent`** — CRUD операций над проектами (создание, обновление, удаление, изменение видимости).
- **`FeedComponent`** — формирование ленты публичных проектов с пагинацией.
- **`SubscriptionComponent`** — управление подписками пользователей.
- **`PreviewGeneratorComponent`** — растеризация SVG в PNG (для превью) с помощью библиотек (например, Cairo или resvg).

## 3. База данных (PostgreSQL)

Используются три таблицы.

### 3.1. Таблица `users`

Хранит информацию о пользователях.

| Поле         | Тип               | Описание                                                     |
|--------------|-------------------|--------------------------------------------------------------|
| `id`         | `BIGSERIAL` PK    | Уникальный идентификатор пользователя.                       |
| `login`      | `VARCHAR(64)` NOT | Уникальное имя пользователя (никнейм).                       |
| `email`      | `VARCHAR(128)`    | Email (используется для входа, должен быть уникальным).      |
| `password`   | `VARCHAR(255)`    | Хеш пароля                                                   |
| `projects`   | `BIGINT[]`        | Список ID проектов пользователя                              |

> **Примечание**: поле `projects(id)` — это неатомарный подход. Лучше вынести связи в отдельную таблицу `user_projects`, но если вы решите хранить массив ID в JSONB, это допустимо для упрощения.

### 3.2. Таблица `projects`

Хранит метаданные проектов. Сами данные (векторное представление) хранятся в объектном хранилище, в таблице — только ссылка и метаинформация.

| Поле            | Тип               | Описание                                                                 |
|-----------------|-------------------|--------------------------------------------------------------------------|
| `id`            | `BIGSERIAL` PK    | Уникальный идентификатор проекта.                                        |
| `name`          | `VARCHAR(255)`    | Название проекта.                                                        |
| `description`   | `TEXT`            | Текстовое описание желаемого стиля (ввод пользователя).                  |
| `chat_history`  | `JSONB` или `TEXT`| Массив сообщений чата с ИИ                                               |
| `created_at`    | `TIMESTAMP`       | Дата создания проекта.                                                   |
| `is_private`    | `BOOLEAN` DEFAULT | `true` — приватный (видит только автор), `false` — публичный.            |

## 4. Взаимодействие компонентов (примерный flow)

1. **Пользователь создаёт проект**:
   - `ProjectManagerComponent` создаёт запись в БД (`projects`).
   - Вызывается `PromptConstructorComponent` для формирования промпта с помощью `VectorSearchComponent` (подбор примеров).
   - Полученный промпт передаётся в `LLMClientComponent` → получаем сгенерированные данные.
   - `VersionStorageComponent` сохраняет первую версию в объектное хранилище.
   - Данные возвращаются клиенту.

2. **Пользователь отправляет сообщение в чат правок**:
   - В `ProjectManagerComponent` добавляется сообщение в `chat_history`.
   - `PromptConstructorComponent` строит промпт на основе текущего состояния (загружается последняя версия из объектного хранилища) + нового сообщения.
   - Вызов `LLMClientComponent` → обновлённые данные.
   - `VersionStorageComponent` сохраняет новую версию.
   - Обновляется поле `diff` в таблице `projects` (опционально).

3. **Пользователь правит вручную через фронтенд-редактор**:
   - Редактор отправляет изменённые данные на бэкенд.
   - `ProjectManagerComponent` обновляет текущее состояние проекта (в объектном хранилище).
   - `VersionStorageComponent` сохраняет новую версию с источником `manual`.

4. **Просмотр истории**:
   - `VersionStorageComponent` выдаёт список версий из мета-таблицы.
   - При восстановлении — загружает данные конкретной версии и сохраняет как новую (или перезаписывает текущую).
