# SVG-контракт проекта

Этот документ фиксирует формат поля `data` проекта для бэкенда, LLM и
фронтенд-редактора. Контракт нужен, чтобы сгенерированный SVG можно было
безопасно сохранить, отобразить и редактировать как набор слоёв.

## 1. Транспортный формат

- API передаёт документ в JSON-поле `data` как UTF-8 строку с полной
  SVG-разметкой.
- `GET /projects/{id}` возвращает `data`; `PATCH /projects/{id}` принимает
  `data`; `POST /projects/{id}/generate` возвращает новое `data`.
- Каждое сохранённое или сгенерированное значение `data` — полный снимок
  документа, а не diff.
- До сохранения бэкенд валидирует SVG по этому документу. Если проверка не
  пройдена, возвращает `422 Unprocessable Entity` и список ошибок.

## 2. Корневой элемент и холст

Документ обязан содержать ровно один корневой `<svg>`:

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 500 500">
```

Обязательные условия:

- `xmlns` строго равен `http://www.w3.org/2000/svg`;
- `viewBox` обязателен и содержит четыре конечных числа `minX minY width height`;
- `width` и `height` в `viewBox` больше нуля;
- атрибуты `width` и `height` на корневом элементе необязательны и не задают
  модель координат редактора: источником истины остаётся `viewBox`;
- XML declaration разрешена, но не обязательна; `DOCTYPE` и пользовательские
  XML entities запрещены. Стандартные экранирования текста (`&amp;`, `&lt;`,
  `&gt;`, `&quot;`, `&apos;`) разрешены.

Для первого релиза рекомендуется использовать `viewBox="0 0 500 500"`.
Другие размеры допустимы, если фронтенд читает `viewBox` и масштабирует сцену.

## 3. Структура слоёв и идентификаторы

### 3.1. Редактируемые слои

Каждый редактируемый слой — элемент SVG или группа `<g>` с уникальным `id`.
Для групп-слоёв дополнительно обязательны:

```svg
<g id="logo" data-editor-layer="true" data-name="Логотип">
```

- `id` уникален во всём документе, не меняется при AI-правках, если элемент
  сохраняет свой смысл;
- допустимый формат ID: `^[a-z][a-z0-9-]{0,63}$`;
- `data-name` — необязательное, понятное человеку название для панели слоёв;
- вложенность групп разрешена; максимальная глубина — 16;
- порядок дочерних элементов определяет порядок отрисовки: элемент ниже в SVG
  находится визуально выше;
- если AI добавляет новый слой, он обязан дать ему новый уникальный ID; если
  удаляет слой, удаляет весь элемент с этим ID.

`id` — единственный ключ, по которому фронтенд сопоставляет SVG, выделение,
историю и изменение свойств. Нельзя использовать автоматически меняющиеся ID.

### 3.2. Поддерживаемые элементы

Разрешены только:

- контейнеры: `svg` (только корневой), `g`;
- фигуры: `path`, `rect`, `circle`, `ellipse`, `line`, `polyline`, `polygon`;
- текст: `text`, `tspan`;
- определения цвета: `defs`, `linearGradient`, `radialGradient`, `stop`.

Любой другой элемент отклоняется до его явного добавления в контракт. В
частности запрещены: `script`, `style`, `foreignObject`, `iframe`, `image`,
`use`, `symbol`, `marker`, `filter`, `mask`, `clipPath`, анимации и все
SMIL-элементы.

`path` допустим для отображения и перемещения как целый слой. Его точечное
редактирование (узлы контура) не входит в первый релиз.

## 4. Геометрия, стили и transform

### 4.1. Геометрические атрибуты

Используются обычные SVG-атрибуты: `x`, `y`, `x1`, `y1`, `x2`, `y2`, `cx`,
`cy`, `r`, `rx`, `ry`, `width`, `height`, `d`, `points`, `offset`.

- Числа должны быть конечными (`NaN` и `Infinity` запрещены).
- Проценты, единицы измерения (`px`, `em`, `cm`) и вычисления CSS запрещены:
  координаты задаются только числами в системе `viewBox`.
- Для `path` разрешены команды `M`, `L`, `H`, `V`, `C`, `S`, `Q`, `T`, `A`, `Z`
  в верхнем и нижнем регистре.

### 4.2. Стили

Разрешены только presentation-атрибуты:

`fill`, `fill-opacity`, `stroke`, `stroke-opacity`, `stroke-width`,
`stroke-linecap`, `stroke-linejoin`, `opacity`, `font-family`, `font-size`,
`font-weight`, `font-style`, `text-anchor`, `stop-color`, `stop-opacity`.

- Инлайн-атрибут `style` и CSS-правила запрещены.
- Цвета допускаются только как hex (`#RGB`, `#RRGGBB`, `#RRGGBBAA`), `none` или
  локальная ссылка на градиент `url(#gradient-id)`.
- В `font-family` разрешены только заранее согласованные web-safe шрифты:
  `Arial`, `Helvetica`, `Inter`, `Roboto`, `sans-serif`, `serif`, `monospace`.
- Внешние URL, `data:`-URL и ссылки на внешние ресурсы запрещены во всех
  атрибутах.

### 4.3. Преобразования

Пользовательское позиционирование задаётся атрибутом `transform` на самом
редактируемом элементе или на группе-слое. Это предпочтительнее изменения
геометрии всех вложенных элементов.

Допустим только такой порядок операций:

```svg
transform="translate(tx ty) rotate(angle cx cy) scale(sx sy)"
```

- разрешены `translate`, `rotate`, `scale`;
- операции идут только в указанном порядке; отсутствующие операции можно
  опустить;
- `matrix`, `skewX`, `skewY`, CSS `transform` и `transform-origin` запрещены;
- `sx` и `sy` больше нуля; `angle` задаётся в градусах;
- фронтенд хранит эти значения отдельно, а при сохранении сериализует их в
  `transform`.

## 5. Текст

- `text` содержит только текстовые узлы и при необходимости `tspan`;
- у каждого редактируемого `text` есть уникальный `id`;
- позиция текста задаётся через `x` и `y`;
- `textPath`, ссылки, HTML и внешние шрифты запрещены;
- максимальная длина текста одного элемента — 1 000 символов.

## 6. Ограничения размера

Бэкенд обязан отклонять SVG, который превышает хотя бы один лимит:

| Ограничение | Значение |
| --- | ---: |
| Размер SVG-строки | 256 KiB |
| Число SVG-элементов | 500 |
| Максимальная вложенность | 16 |
| Длина одного `id` | 64 символа |
| Длина текста одного элемента | 1 000 символов |

Эти лимиты одинаково применяются к `PATCH`, ответу LLM до сохранения и любому
импорту в будущем.

## 7. Что нужно обеспечить бэкенду и LLM

### Бэкенду нужно обеспечить

1. Разобрать SVG XML-парсером, а не проверять строковыми регулярными
   выражениями.
2. Отклонить запрещённые теги, атрибуты, URL и некорректные числа.
3. Проверить уникальность ID, лимиты и корректность `viewBox`.
4. Не сохранять и не отдавать непроверенный SVG, полученный от LLM.
5. Передавать LLM этот контракт вместе с текущим SVG при AI-редактировании.

### LLM нужно настроить так, чтобы она

1. Возвращать только XML/SVG без Markdown, комментариев и объяснений.
2. Использовать только разрешённые элементы и атрибуты.
3. Сохранять ID существующих элементов при изменении их свойств.
4. Давать новые уникальные ID новым элементам.
5. Возвращать целый документ от `<svg>` до `</svg>`.

## 8. Эталонный пример

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 500 500">
  <defs>
    <linearGradient id="accent-gradient" x1="0" y1="0" x2="1" y2="1">
      <stop offset="0" stop-color="#6C3BFF" />
      <stop offset="1" stop-color="#A855F7" />
    </linearGradient>
  </defs>

  <g id="background" data-editor-layer="true" data-name="Фон">
    <rect id="background-rect" x="0" y="0" width="500" height="500" fill="#FFFFFF" />
  </g>

  <g id="logo" data-editor-layer="true" data-name="Логотип" transform="translate(0 0)">
    <circle id="logo-mark" cx="250" cy="205" r="92" fill="url(#accent-gradient)" />
    <path id="logo-cut" d="M215 205 L240 230 L290 180" fill="none" stroke="#FFFFFF"
      stroke-width="18" stroke-linecap="round" stroke-linejoin="round" />
  </g>

  <g id="title" data-editor-layer="true" data-name="Название">
    <text id="title-text" x="250" y="365" fill="#1D1D1F" font-family="Inter"
      font-size="36" font-weight="700" text-anchor="middle">AVATARA</text>
    <text id="subtitle-text" x="250" y="405" fill="#6B7280" font-family="Inter"
      font-size="16" text-anchor="middle">design your identity</text>
  </g>
</svg>
```

## 9. Изменение контракта

Добавление нового тега, атрибута или возможности сначала согласуется между
фронтендом и бэкендом, затем добавляется в этот документ и покрывается
тестовыми SVG-примерами. До этого неподдерживаемые конструкции должны
отклоняться предсказуемо, а не сохраняться «как есть».
