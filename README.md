## О проекте

Онлайн-сервис для генерации брендбуков компаний с помощью ИИ. Пользователь описывает желаемый стиль текстом — LLM генерирует элементы фирменного стиля (логотипы, аватарки, визитки, обложки чатов) в векторном формате. Результат можно точечно доработать в встроенном векторном редакторе или через чат с ИИ. Готовые работы публикуются в профиле и в общей ленте.

## Продуктовые требования

### 1. Аутентификация и профиль пользователя

- Регистрация и вход по email + пароль (или OAuth — на усмотрение команды)
- Онбординг после первой регистрации: краткий рассказ о возможностях продукта (3–4 экрана)
- Страница профиля:
  - Публичная часть: публичные проекты, количество подписчиков и подписок, переход доступен без авторизации
  - Приватная часть (только для владельца): все проекты, включая приватные

---

### 2. Проекты (брендбуки)

Каждый **проект** — это именованный набор элементов фирменного стиля, созданных пользователем.

#### 2.1 Создание проекта

- Пользователь создаёт новый проект, задаёт название и вводит текстовое описание желаемого результата: стиль, цветовая гамма, настроение, символика, индустрия компании и т.п.
- Запрос уходит на бэкенд, где LLM генерирует результат в **векторном формате** (SVG или структурированный JSON — финальный формат согласуется между командами бэкенда и фронтенда до начала реализации)
- Результат отображается во встроенном UI-редакторе (разрабатывается фронтенд-командой, встраивается как `iframe` в мобильное приложение)

#### 2.2 Редактирование через чат с ИИ

- В рамках проекта есть чат, где пользователь описывает правки: «Сделай фон темнее», «Добавь корону», «Измени шрифт на более современный»
- Каждое сообщение отправляется на бэкенд — LLM обновляет текущее состояние проекта
- Каждое изменение через чат фиксируется как новая версия в **истории изменений**

#### 2.3 Ручное редактирование (UI-редактор, фронтенд)

- Встроенный визуальный редактор отображает сгенерированные данные
- Пользователь может: перемещать, масштабировать и вращать элементы; менять цвета, обводки, шрифты; добавлять и удалять элементы; работать со слоями
- Каждое сохранение через редактор также фиксируется в истории изменений
- Поддержка Undo/Redo

#### 2.4 История изменений

- Каждое состояние проекта сохраняется как отдельная версия
- Пользователь видит список версий: дата, источник изменения (чат с ИИ / ручное редактирование), превью
- Возможность откатиться к любой предыдущей версии

#### 2.5 Видимость проекта

| Статус | Кто видит |
|---|---|
| Приватный (по умолчанию) | Только автор |
| Публичный | Все пользователи: в профиле автора и в общей ленте |

- Автор явно переключает статус видимости
- Публичные проекты доступны без авторизации по прямой ссылке

---

### 3. Лента

- **Общая лента** — все публичные проекты всех пользователей, сортировка по дате публикации
- **Лента подписок** — публичные проекты только тех авторов, на которых подписан пользователь
- Переключение между режимами через вкладки «Все» / «Подписки»
- Карточка в ленте: превью проекта, имя автора (переход на его профиль), название проекта, дата публикации

---

### 4. Подписки

- Пользователь может подписаться на другого пользователя со страницы его профиля
- Список подписок и подписчиков доступен в профиле
- Лента подписок фильтруется по подписанным авторам

---

### 5. Экспорт

- Скачивание проекта в форматах: PNG, SVG (опционально — PDF)
- Выбор размера при экспорте: 512×512, 1024×1024 и т.п.
- Скачивание доступно и для публичных проектов без авторизации

## Команды и зоны ответственности

> Нагрузка распределена исходя из состава: **бэкенд — 6–8 человек**, **мобилки — 2–4 человека**, **фронтенд — 2 человека**

### 🖥 Бэкенд (6–8 человек)

**Стек:** C++ (userver) или на усмотрение команды; PostgreSQL; Yandex Object Storage

Бэкенд — самая большая команда, поэтому работа разбита на независимые подзадачи, которые можно вести параллельно.

#### Зоны ответственности

**1. Аутентификация и управление пользователями** *(1–2 человека)*
- Регистрация, вход, выход
- Хранение данных пользователя (профиль, аватар)
- JWT-токены или сессии
- Защита эндпоинтов

**2. Проекты — CRUD и видимость** *(1–2 человека)*
- Создание, чтение, редактирование, удаление проектов
- Управление видимостью (приватный / публичный)
- Хранение метаданных проектов в PostgreSQL

**3. Версионирование проектов** *(1 человек)*
- Сохранение каждого состояния проекта как отдельной версии
- API для получения истории и восстановления версии
- Хранение данных версий (SVG/JSON) в объектном хранилище

**4. Интеграция с LLM — первичная генерация** *(1–2 человека)*
- Подключение к Yandex AI Studio (YandexGPT или другая модель)
- Prompt engineering: генерация SVG/JSON по текстовому описанию пользователя
- Обработка ответа модели, валидация и нормализация формата
- Опционально: RAG — подборка примеров стилей/шаблонов для улучшения генерации (проработать целесообразность)

**5. Интеграция с LLM — редактирование через чат** *(1 человек)*
- Prompt engineering: передача текущего состояния проекта + нового сообщения пользователя в LLM
- Получение обновлённого состояния проекта от модели
- Сохранение новой версии после каждого ответа ИИ

**6. Лента и подписки** *(1 человек)*
- API общей ленты с пагинацией
- API ленты подписок
- API подписки / отписки
- Индексирование публичных проектов для ленты

**7. Хранилище файлов и генерация превью** *(1 человек)*
- Сохранение SVG/JSON-данных проектов и версий в объектном хранилище
- Растеризация SVG в PNG для превью в ленте и профиле
- Отдача файлов по публичным ссылкам

**8. Инфраструктура и CI/CD** *(1 человек, совместно с другими)*
- Docker-контейнеризация бэкенда
- Настройка CI/CD пайплайна
- Настройка базы данных (миграции)
- Деплой на сервер

#### Минимальный список эндпоинтов

```
POST   /auth/register
POST   /auth/login
GET    /users/{id}                          — профиль пользователя
GET    /users/{id}/projects                 — проекты пользователя

POST   /projects                            — создать проект
GET    /projects/{id}
PATCH  /projects/{id}                       — обновить метаданные / видимость
DELETE /projects/{id}

POST   /projects/{id}/generate             — первичная генерация через LLM
POST   /projects/{id}/chat                 — редактирование через чат с ИИ

GET    /projects/{id}/versions/{vid}       — конкретная версия
POST   /projects/{id}/versions/{vid}/restore

GET    /feed                               — общая лента (пагинация)
GET    /feed/subscriptions                 — лента подписок

POST   /users/{id}/subscribe
DELETE /users/{id}/subscribe
GET    /users/{id}/subscribers
GET    /users/{id}/subscriptions
```

### 🎨 Фронтенд — UI-редактор (2 человека)

**Стек:** React / Vue / Svelte (на усмотрение), SVG DOM или Fabric.js / Konva.js

Фронтенд-команда делает **один продукт** — встраиваемый векторный редактор. Он работает как самостоятельное веб-приложение, которое подключается через `iframe` в мобильное приложение.

#### Зоны ответственности

**Человек 1 — ядро редактора и canvas**
- Рендеринг SVG/JSON-данных от бэкенда на canvas
- Инструменты работы с элементами: выделение, перемещение, масштабирование, вращение
- Undo/Redo механизм

**Человек 2 — панели и экспорт**
- Панель слоёв (список элементов, порядок, видимость)
- Панель свойств (цвет, обводка, шрифт, позиция, размер)
- Верхний тулбар (инструменты, зум, сохранение)
- Экспорт в PNG и SVG
- Адаптация интерфейса для встраивания в `iframe` (мобильная версия с touch-управлением)

#### Ключевая задача к Демо 1

Согласовать с бэкендом **финальный формат данных** (SVG или JSON-схему) и задокументировать его — это разблокирует работу мобильной команды и бэкенда на модуле генерации.

#### Функциональные требования к редактору

- Принимает данные от бэкенда (SVG или JSON-граф элементов) и отображает их
- Позволяет ручное редактирование: перемещение, масштабирование, вращение, цвета, шрифты, слои
- Отдаёт изменённые данные обратно в формате, понятном бэкенду (для сохранения версии)
- Поддерживает Undo/Redo
- Кнопки экспорта: скачать PNG, скачать SVG
- Работает в двух режимах: standalone (полный интерфейс) и iframe (упрощённый тулбар, touch-friendly)

### 📱 Мобильное приложение (2–4 человека)

**Стек:** iOS (Swift/SwiftUI) и/или Android (Kotlin/Jetpack Compose) — на усмотрение команды

Мобильная команда реализует весь пользовательский интерфейс приложения. Редактор встраивается через WebView/`iframe` — его разрабатывает фронтенд-команда.

#### Распределение экранов

**Человек 1 — Онбординг и аутентификация**
- Онбординг (3–4 экрана): рассказ о продукте, анимированные иллюстрации
- Экран регистрации (email, пароль)
- Экран входа
- Навигационный скелет приложения (bottom tab bar, роутинг)

**Человек 2 — Лента и профиль**
- Лента: общая + лента подписок (вкладки), бесконечный скролл, карточки проектов
- Страница профиля: своя + чужая, публичные проекты, подписки/подписчики
- Кнопка «Подписаться» / «Отписаться» на чужом профиле

**Человек 3 — Создание и редактирование проекта** *(при наличии 3+ человек)*
- Экран создания проекта: ввод названия и текстового описания, запуск генерации, индикатор загрузки
- Экран проекта: область WebView с фронтенд-редактором + чат с ИИ снизу
- Переключатель видимости (приватный / публичный)
- Кнопки сохранения и публикации

**Человек 4 — История и детали проекта** *(при наличии 4 человек)*
- Экран истории изменений: список версий, превью, источник (ИИ / вручную), кнопка «Восстановить»
- Экран публичного проекта (просмотр без редактирования): превью, автор, кнопка скачивания
- Экран чата с ИИ: история сообщений, ввод, превью ответов ИИ

> При команде из 2 человек экраны делятся поровну: один берёт онбординг + аутентификацию + профиль, второй — ленту + создание/редактирование проекта + историю.

## Формат данных (согласовать к Демо 1)

Финальный формат передачи данных между бэкендом и фронтенд-редактором необходимо зафиксировать и задокументировать **до начала активной разработки**.

**Варианты:**

1. **SVG** — бэкенд возвращает готовый SVG-файл, редактор работает напрямую с SVG DOM
2. **JSON-граф элементов** — бэкенд возвращает JSON с описанием элементов (тип, позиция, размер, цвет, контент), редактор рендерит из JSON и сохраняет изменения обратно в JSON

Рекомендация: рассмотреть JSON-подход как более гибкий для итеративного редактирования через ИИ.

## Глоссарий

| Термин | Значение |
|---|---|
| Проект / Брендбук | Набор элементов фирменного стиля, созданных пользователем |
| Версия | Одно зафиксированное состояние проекта (создаётся при каждом изменении) |
| Публичный проект | Виден всем в ленте и по прямой ссылке |
| Приватный проект | Виден только автору |
| Лента | Общий поток публичных проектов всех или подписанных пользователей |
| Редактор | Веб-приложение (`iframe`), реализуемое фронтенд-командой |
| LLM | Языковая модель, генерирующая и редактирующая элементы брендбука |
| RAG | Retrieval-Augmented Generation — метод улучшения генерации через подборку релевантных примеров |
