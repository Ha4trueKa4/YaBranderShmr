# SVG: правила интеграции и поведения редактора

Этот документ — технический контракт для фронтенда и бэкенда. Его цель —
сохранить и показать результат генерации, даже когда редактор ещё не умеет
редактировать часть SVG. Он дополняет компактный промпт в
`SVG_GENERATION_PROMPT.md`; промпт не является валидатором и не должен
разрастаться до описания реализации.

## Принцип

Возможность отредактировать элемент не определяет, можно ли принять SVG.
Редактор обязан разделять документ на:

- **редактируемые узлы** — текущие поддерживаемые `g`, `rect`, `circle`,
  `ellipse`, `line`, `path` и простой `text` с понятными атрибутами;
- **заблокированные узлы** — любой иной безопасный SVG-элемент либо
  поддерживаемый элемент с пока неподдерживаемыми атрибутами, стилем или
  содержимым. Он отображается как `raw`-слой с иконкой Lock, но без панели
  редактирования;
- **небезопасное содержимое** — скрипты, обработчики событий, `foreignObject`,
  `iframe` и внешние ссылки. Его нельзя передавать в рендерер: удалить или
  нейтрализовать до создания `raw`-слоя и добавить предупреждение импорта.

Такой узел не является ошибкой документа. Его исходная разметка должна
сохраниться при последующей сериализации, чтобы сохранение правок других
слоёв не ломало изображение.

## Поведение API и генерации

1. Бэкенд применяет проверку как диагностику качества и безопасности, а не
   как причину отменить удачную генерацию из-за неподдерживаемой функции
   редактора.
2. Если генератор вернул безопасный, корректный SVG, но advisory-валидатор
   нашёл неизвестный тег, атрибут или превышение «рекомендуемого» ограничения,
   API всё равно возвращает SVG/картинку и успешный результат. Диагностику
   можно записать в логи или вернуть отдельным массивом предупреждений.
3. Нельзя вернуть ошибку генерации лишь потому, что SVG не соответствует
   желательным правилам промпта или не полностью редактируется на фронтенде.
4. Жёстко обрабатывать отдельно только безопасность и техническую
   неотображаемость: некорректный XML, отсутствие корневого SVG либо
   корректного `viewBox`, опасная разметка. Для таких случаев нужен безопасный
   fallback (повторная генерация, санитизация и/или заранее согласованный
   raster-preview), а не попытка отрисовать исходную строку как HTML.
5. Сохранение пользовательских правок не должно удалять неизвестные
   безопасные фрагменты. Если сервер дополнительно очищает SVG, он обязан
   делать это идемпотентно и не менять безопасную визуальную часть без явной
   причины.

## Что поддержано сейчас

Редактор может изменять геометрию/свойства доступных фигур, текста и групп,
а также отображает `linearGradient` и `radialGradient` из `<defs>`.
Неподдерживаемые определения сохраняются как raw-разметка. `path` доступен
как слой, но его точки контура не редактируются.

Текущее представление в коде: `EditorRawNode` (`type: 'raw'`,
`isLocked: true`, `rawSvg`) и предупреждение `locked-raw-node`.

## Что необходимо поддерживать в коде

1. Парсер должен быть tolerant после успешного разбора XML и проверки корня:
   ошибка разбора отдельного узла, неизвестный тег либо атрибут создаёт
   заблокированный raw-узел, а не прерывает импорт всего документа.
2. Генерировать `data-editor-id` и `data-name` для импортированных узлов без
   идентификатора. Идентификаторы должны быть уникальными в модели редактора.
3. Перед `dangerouslySetInnerHTML` обязательно санитизировать raw-фрагмент.
   Правила санитизации должны запрещать активный контент и внешние ресурсы, но
   не удалять безопасные неизвестные SVG-возможности только потому, что они не
   редактируются.
4. При добавлении нового редактируемого типа сначала оставить прежний
   tolerant fallback, затем добавить: модель, парсинг, отрисовку,
   сериализацию, панель свойств и тест с импортом/повторным сохранением.
5. Предупреждения импорта — наблюдаемая диагностика, а не причина показывать
   пользователю экран ошибки. Экран ошибки остаётся только для документа,
   который невозможно безопасно разобрать в SVG-сцену.

## Критерии приёмки

- SVG с `polygon`, `tspan`, `clipPath`, `filter` или неизвестным безопасным
  атрибутом открывается без падения; соответствующий фрагмент виден как
  заблокированный слой.
- Правка поддерживаемого соседнего слоя и сохранение не удаляет этот raw
  фрагмент.
- `script`, event-атрибуты и внешние URL не попадают в итоговый DOM.
- Некорректный XML и SVG без рабочего `viewBox` не приводят к аварии:
  приложение показывает контролируемую ошибку/резервный результат.
- Бэкенд не отвечает ошибкой только из-за предупреждения о совместимости;
  генерация возвращает доступный для показа результат.
